Rules file for AI. User pastes a minimal invocation (see `AGENT_PROMPTS.md`); do NOT expect this file's content in the prompt.

## Rules

Execute in order.

1. **Check the script exists** at `scripts/setup-5.mjs` (repo root). If missing → **STOP**: "ไม่พบ scripts/setup-5.mjs — ต้องติดตั้งสคริปต์ก่อน (ดู AGENTS.md Section 4)". **Do NOT create, write, or reconstruct the script.**

2. **Run exactly this command** from the repo root (quote any value that contains spaces):

   ```
   node scripts/setup-5.mjs <project> <access-flow> <module> <feature>
   ```

   Run it once. Do not add flags. Do not retry with different values.

3. **Read the output and report** (see "Reporting" below).

## Reporting

### Exit code 0 (✅)

Tell the user in the user's language (the language they wrote the prompt in):

- Where the files were created
- Locator count, TC count, flow line counts (from script output)
- Any `⚠️` warnings, with the fix from the table below
- Next step: the `npx playwright test ...` command printed by the script

### Exit code 1 (❌)

The script wrote **nothing**. Show its error message as-is, then tell the user which setup to revisit:

Route by **which file the message names** (every source-file error starts with its path):

| Message names / says | Go to |
|---|---|
| `…/_flows/<feature>.ts` (marker missing/duplicated/out of order, `"});"` not found) | Dev fixes `_flows/<feature>.ts` (AGENTS.md Section 5) |
| `…/_locators/<feature>.ts` or starts with `_locators` | Setup 3 |
| `…/_scenarios/<feature>.csv` or starts with `_scenarios` | Fix each listed row in the CSV, or rerun Setup 4 |
| ไม่พบไฟล์ต้นทาง / Source file missing | Missing file(s) listed: `_flows/` → dev, `_locators/` → Setup 3, `_scenarios/` → Setup 4 |
| … มีอยู่แล้ว / … already exists | Setup 7 (update TCs) — or the user deletes the folder manually to regenerate |
| ต้องระบุ 4 ค่า / 4 values required | Ask the user to complete the Location block |

Corruption messages (garbled text, `�`, UTF-16, `` `n ``) follow the same routing — by the file they name.

For `⚠️ authType … invalid` / `ไม่ถูกต้อง` → user fixes `project.config.json` to `none` / `microsoft` / `form` (or rerun Setup 1 Create-Project for any new module — it corrects invalid values).

For any error not in this table → show the message and stop. Do not guess a fix.

Keep the report short, in the user's language. Do not paste the generated files.
