# Setup 6 — Extend Helper (Rules)

Rules file for AI. User pastes a minimal invocation (see `doc/GUIDE.md` Appendix A).

Adds ONE new capability to ONE feature's `helper.ts`: a new `|action`, or a new static locator type. This is judgment work — you design the code, the user reviews it.

---

## What the user paste looks like

```markdown
### Setup 6 — Extend action

Read: #file:prompts/setup-6-extend-action.md

**Location**
- Project: <project>
- AccessFlow: <access-flow>
- Module: <module>
- Feature: <feature>

**Extension**
<error message, or what is needed — e.g. "|download: wait for the file download after clicking">
```

The Extension text is free-form (the user may not know code). You decide:
- **Type:** `action` (new `|name` marker) or `locator` (new static locator kind that should receive text)
- **Name** (action) or **detection pattern** (locator)
- **Implementation** (Playwright code)

If you cannot tell what behavior is wanted → **STOP** and ask one clarifying question. Do not guess.

---

## Scope

- Modify **only** `Test-Local/<project>/<access-flow>/<module>/<feature>/<feature>.helper.ts`
- Do NOT modify: `spec.ts`, `data.ts`, `types.ts`, `_flows/`, `_locators/`, `_scenarios/`, `AGENTS.md`, `scripts/`, other features
- Do NOT run tests or terminal commands
- Change nothing in the helper except the one insertion below (no reformatting, no renaming, no "improvements")

### File writing

- Use file edit tools (`str_replace` / insert). **Never** PowerShell or any shell.
- UTF-8 without BOM. Real newlines.

## Helper structure (generated by `scripts/setup-5.mjs`)

```typescript
const locators: ReadonlyArray<(page: Page, value?: string) => Locator> = <feature>Locators;

async function applyItem(page: Page, index: number, item: string): Promise<void> {
  const locatorFn = locators[index];
  ...
  if (item.startsWith('|')) {
    const action = item.slice(1);
    switch (action) {
      case 'click': { ... }
      // ← (A) new action case goes here, above default
      default:
        throw new Error(`Unknown action: |${action}`);
    }
  }

  if (locatorFn.length === 2) { ... }   // parametric

  const target = locatorFn(page);        // static only — defined HERE, not in the switch
  const locatorCode = locatorFn.toString();

  if (/getByRole\(\s*['"]textbox['"]/.test(locatorCode)) {
    ...
  // ← (B) new locator branch goes here, before the final else
  } else {
    await selectOption(page, target, item);   // everything else = dropdown
  }
}
```

**`target` does NOT exist inside the action switch.** Use `locatorFn(page)` there.

## Rules

1. Verify the feature folder and `<feature>.helper.ts` exist. Missing → **STOP**: `Setup 5 required`.
2. Read the helper. If it does not match the structure above (e.g. an old AI-written helper) → **STOP**: `helper.ts is not the setup-5.mjs format — regenerate with Setup 5 first`.
3. Decide Type / Name / implementation from the Extension text.

### Type = action → insert at (A)

4a. If `case '<name>':` already exists → **STOP**: `Action '|<name>' already exists`.
    Name: lowercase letters only (`download`, `check`, `hover`).

5a. Insert exactly this shape above `default:`:
```typescript
      case '<name>': {
        if (locatorFn.length === 2) {
          throw new Error(
            `Locator at index ${index} is parametric — |<name> needs a static locator`
          );
        }
        // implementation using locatorFn(page) and page
        return;
      }
```

Example — `|download`:
```typescript
      case 'download': {
        if (locatorFn.length === 2) {
          throw new Error(
            `Locator at index ${index} is parametric — |download needs a static locator`
          );
        }
        const downloadPromise = page.waitForEvent('download');
        await locatorFn(page).click();
        await downloadPromise;
        return;
      }
```

Example — `|check`:
```typescript
      case 'check': {
        if (locatorFn.length === 2) {
          throw new Error(
            `Locator at index ${index} is parametric — |check needs a static locator`
          );
        }
        await locatorFn(page).check();
        return;
      }
```

### Type = locator → insert at (B)

4b. Choose a detection pattern that appears in the locator source (from `_locators/<feature>.ts`, read-only). It must NOT be caught by an earlier branch — branches are checked in order, so a locator containing `getByRole('textbox'` will never reach your branch.
    If an existing branch already matches that locator → **STOP** and explain which branch catches it.

5b. Insert before the final `} else {`:
```typescript
  } else if (locatorCode.includes('<pattern>')) {
    // implementation using target, item, page
```

Example — datepicker:
```typescript
  } else if (locatorCode.includes('date-picker-input')) {
    await target.click();
    await page.getByRole('gridcell', { name: item }).click();
```

### Show the change

6. Show the user the inserted code block and one sentence on what it does.

## Output (in the user's language (the language they wrote the prompt in))

- Added: action `|<name>` / locator type `<pattern>` → what it does
- Scope: **this feature only**. Other features do not have it.
- Next:
  1. Use it in the CSV (e.g. `|download` at the right position), edit in VS Code
  2. **Setup 7** (Run Task) — accepts the new action because it reads this helper
  3. Run the test
- Warning: if this feature folder is deleted and Setup 5 is rerun, this extension is lost (Setup 5 regenerates helper.ts from the template)
- Tell the dev if it should become standard for all future features: they add it to the helper template in `scripts/setup-5.mjs` and to AGENTS.md Section 9
