## Section 1: Project Overview

**ttest-playwright** = universal Playwright test runner supporting multiple projects with different auth mechanisms. Target users include QA who do not write code — they drive the framework through VS Code Tasks and setup prompts (`doc/GUIDE.md`).

**Structure:** nested only (one folder per feature). Flat structure is not supported.

### Auth types

`project.config.json` lives at the **access flow** level (not module level). Valid values:

| authType | Mechanism |
|---|---|
| `none` | Public pages, no login |
| `microsoft` | Azure AD SSO — persistent Chromium profile |
| `form` | Email/password login — session storage |

```json
{
  "authType": "none"
}
```

Empty string `""` is **invalid**. If the file is missing, the runner defaults to `none`.

### Three module-level folders

| Folder | Owner | Committed? | Purpose |
|---|---|---|---|
| `_flows/` | Dev | ✅ | Flow template with SETUP / PER TEST / DATA markers |
| `_locators/` | Dev | ✅ | Ordered array of locator functions — **imported by helper.ts at runtime** |
| `_scenarios/` | **QA** | ✅ | Test scenarios (CSV) — 1 row per TC |

All three are committed so anyone who clones the repo can run tests and regenerate features.

### What counts as a feature?

One user-facing action with its own success criteria. Multiple actions on the same page = different features:
- `Dashboard/search` — filter records
- `Dashboard/print` — print work order
- `Bookings/bookings` — customer creates a booking

## Section 2: Universal Principles

### Core principle

> **Locator = WHERE. Value = WHAT.**

| Element | Locator (dev) says | CSV value (QA) says |
|---|---|---|
| textbox | which field | text to type |
| combobox | which dropdown | which option to pick |
| button — parametric | which group of buttons | which button (by name) |
| button — static | which exact button | `|click` |

### Design principles

1. **Dev owns selectors** — AI and QA never invent selectors. Selectors come from dev's codegen in `_flows/` and `_locators/`.
2. **Order is source of truth** — `_locators/` index N ↔ CSV Value item N.
3. **Universal helper** — no per-feature action taxonomy. Helper dispatches by value content and locator shape (Section 9).
4. **CSV drives test data** — Value column determines what each TC does at the DATA point.
5. **Mechanical work is done by scripts, not AI** — Setup 1, 2, 5, 7 are scripts (run via VS Code Task or by the agent). AI is used where judgment is needed (Setup 3, 6) or multi-line input comes from chat (Setup 4).

### File writing rules (all setups)

- Use file tools directly (`create_file`, `str_replace`, or equivalent).
- **Never** write file content with PowerShell, cmd, or bash (`Out-File`, `Set-Content`, `echo >`, heredoc).
- Encoding MUST be UTF-8 without BOM. Thai text must be preserved exactly.
- Never write escape sequences like `` `n `` or `` `t `` into files.

**Why:** PowerShell `Out-File` writes UTF-16 and corrupts Thai (`à¸Šà¸·à¹ˆà¸­`); shell escapes leak literal `` `n `` into files.

**Exception:** Setup 1, 2, 5, 7 run `node scripts/...` in the terminal. The script writes the files (UTF-8), not the shell. These are the only setups that run a terminal command.

### Locator rules (for HUMAN-written codegen)

- Prefer role-based selectors: `page.getByRole('button', { name: 'ค้นหา' })`
- Never use auto-generated IDs (`#radix-*`, `#mat-*`, UUIDs)
- Avoid `page.locator('span').first()` or similar generic selectors — they flake on slow networks and cold starts
- Avoid `exact: true` with Thai labels containing `/`, spaces, or special chars
- Preserve Thai UI text exactly as it appears in the app
- If you own the app and a button has no accessible name, add `aria-label` instead of relying on `.nth()`

### Verification

- Generated spec includes `defaultVerify`: no visible error dialog + URL still on the same origin as SETUP's `page.goto`
- Test artifacts (`screenshot: 'on'`, `video: 'retain-on-failure'`, `trace: 'on-first-retry'`) provide visual evidence
- Add feature-specific `expect(...)` inside `defaultVerify` after generation when needed

### Security (never commit)

- `.env` (form login credentials)
- `Test-Local/**/_login/session-storage.json` (and legacy `state.json`)
- `Test-Local/**/_login/login-locators.ts` (scratch file for a pasted login recording)
- `Authen/Microsoft/profile/`, `Authen/Microsoft/state.json`
- `.agent-cache/*.json`

Never put passwords in `_flows/` — it is committed, and SETUP is copied into spec.ts.

## Section 4: Setups

7 setup commands. Paste templates: `doc/GUIDE.md` Appendix A.

**Two ways to run a script setup (1, 2, 5, 7):**

| Way | How | When |
|---|---|---|
| **VS Code Task** (fastest) | `Ctrl+Shift+P` → Run Task → pick setup → fill boxes | Default for VS Code / Cursor users |
| **Agent prompt** | Paste template in Copilot Agent mode | Other editors, or when you want the agent to explain errors |

Both run the same script with the same result.

**Project init:**
- **Setup 1 — Create-Project** — project + access flow + module + `project.config.json` + `_flows/ _locators/ _scenarios/` (with `.gitkeep`). Runs `scripts/create-project.mjs`. Also used to add another module or access flow to an existing project.
- **Setup 2 — Form login** — `form` access flows only: converts a recorded login pasted into the git-ignored scratch file `_login/login-locators.ts` into `_login/login.setup.ts` (username/password become variables), then clears the scratch file. Agents must never open `login-locators.ts` (it may hold a real password). Runs `scripts/form-login.mjs`. Then `Authen/Form-Login/setup-form-auth.bat` saves the session.

**Per feature:**
- **Setup 3** — Bootstrap locators (raw codegen → array, classify parametric/static)
- **Setup 4** — Create scenarios CSV, or append new scenarios to an existing one
- **Setup 5** — Create feature (runs `scripts/setup-5.mjs`)

**Maintenance:**
- **Setup 6** — Extend helper vocabulary (new locator type or `|action`)
- **Setup 7** — Update TCs (regenerate `data.ts`)

### Setup 1 — Create-Project

**Signal:** New project, new access flow, or new module.

**Action:**
```
node scripts/create-project.mjs <Project> <AccessFlow> <Module> <none|microsoft|form>
```
Creates missing folders + config. Existing project/access flow are reused. Stops (creating nothing) if: module exists, AuthType invalid, access flow already has a different authType, a name differs from an existing folder only by letter case, or a name contains spaces/invalid characters. An existing config with `""` or an invalid value is corrected.

### Setup 5 — New feature

**Signal:** Feature folder doesn't exist.

**Action:** Agent runs
```
node scripts/setup-5.mjs <Project> <AccessFlow> <Module> <feature>
```
and reports the script output to the user. The agent does NOT write or edit the 4 files itself. If the script fails, the agent reports the error message and which earlier setup to revisit — it does not patch generated files.

Requires Copilot **Agent mode** (terminal access). User approves the command once.

### Setup 6 — Extend helper capability

**Signal:** Helper throws "unknown locator type" or "Unknown action".

**Action:** AI adds one action case (`|action`) or one locator detection branch to **this feature's** `helper.ts` only (AI designs the code from the user's free-text request; user reviews). Does not edit AGENTS.md or other files. Then Setup 7 accepts the new action (it reads the helper). To make an extension standard for all future features, dev adds it to the helper template in `scripts/setup-5.mjs` and to Section 9.

**Caveat:** deleting the feature folder and rerunning Setup 5 regenerates helper.ts and drops per-feature extensions.

### Setup 7 — Update test cases

**Signal:** Feature exists. QA updated CSV or dev updated `_locators/` (CSV must be updated to the new locator count first).

**Action:** Agent runs
```
node scripts/setup-5.mjs <Project> <AccessFlow> <Module> <feature> --data-only
```
Rewrites `data.ts` only; reports added/removed TC-IDs. Allowed `|actions` are read from the feature's `helper.ts`, so Setup 6 additions are accepted. Does NOT touch spec.ts, helper.ts, types.ts.

### Decision tree

```
Change needed
    │
    ├─► Feature folder exists?
    │     │
    │     ├─► No  ─► Setup 5
    │     │
    │     └─► Yes ─► New locator type or |action needed?
    │               ├─► Yes ─► Setup 6
    │               └─► No  ─► Setup 7
```

## Section 5: Source Files

### `_flows/<feature>.ts` — flow template (dev-owned)

Full skeleton of ONE typical TC, with 3 markers (each exactly once, in this order):

```typescript
import { test, expect } from '@playwright/test';

test('test', async ({ page }) => {
  // === SETUP ===
  await page.goto('http://localhost:8787/');

  // === PER TEST ===
  await page.locator('#top').getByRole('link', { name: 'จองเลย →' }).click();

  // === DATA ===
  await page.getByRole('button', { name: 'ยืนยันการจอง →' }).click();
  await page.getByRole('link', { name: 'กลับหน้าแรก' }).click();
});
```

| Section | Goes into spec.ts as |
|---|---|
| SETUP → PER TEST | `enter<Feature>Page()` (runs in `beforeEach`) |
| PER TEST → DATA | test body, before inputs |
| after DATA | test body, after inputs |

**Rules:**
- The `test('test', ...)` wrapper from codegen is optional — the script strips it
- Put the full URL in SETUP's `page.goto(...)` — it is used for `defaultVerify`
- Need to wait for a loading overlay? Write `await waitForLoading(page);` explicitly in `_flows/` — it is never inserted automatically
- Everything is copied **literally** — `_flows/` must be clean and complete

**Pure-action case (e.g., Print):** SETUP + empty PER TEST + DATA marker only; the locator array does the work.

### `_locators/<feature>.ts` — locator array (dev-owned)

```typescript
import type { Locator, Page } from '@playwright/test';

export const bookingsLocators: Array<(page: Page, value?: string) => Locator> = [
  (page, value) => page.getByRole('button', { name: value }),
  (page, value) => page.getByRole('button', { name: value }),
  (page, value) => page.getByRole('button', { name: value }),
  (page) => page.getByRole('textbox', { name: 'ชื่อ-นามสกุล' }),
  (page) => page.getByRole('textbox', { name: 'เบอร์โทร' }),
];
```

**Rules:**
- Export name: `<featureCamelCase>Locators`
- Type: `Array<(page: Page, value?: string) => Locator>`. Older `Array<(page: Page) => Locator>` is accepted only if there are no parametric locators.
- Order = index in CSV Value
- **No comments** describing locators (semantics live in CSV Scenario column)
- Cover every field/button any TC references

**Two locator shapes (produced by Setup 3):**

| Shape | Signature | When |
|---|---|---|
| **Parametric** | `(page, value) => page.getByRole('<role>', { name: value })` | Named choice picked per TC — roles `button`, `link`, `tab`, `radio`, `checkbox`, `switch`, `menuitem*`, `treeitem` (e.g., 1 of 8 services) |
| **Static** | `(page) => ...` | Textbox, combobox, link, fixed/positional button (`.nth(2)`) |

**Parametric contract:** exactly 2 parameters, **no default value**. `(page, value = '') => ...` is forbidden — it makes `fn.length` return 1 and breaks dispatch.

`.nth()` on textbox/combobox identifies a **field** (same for every TC) → static.

### `_scenarios/<feature>.csv` — test scenarios (QA-owned)

```csv
TC-ID,Module,Feature,Scenario,Value
TC001,Bookings,Bookings,จองนวดไทย,"นวดไทย ฿ 350 60 นาที,วันพฤหัสบดีที่ 1 ตุลาคม,11:00,test,0812345678"
TC001,Dashboard,Search,Search by Receipt,"HQ0000020,,,,,,,,,,,"
TC030,Dashboard,Print,Print Job Sheet,"|click"
```

**Rules:**
- Header exactly: `TC-ID,Module,Feature,Scenario,Value`
- TC-ID unique
- Wrap Value in `"..."` whenever it contains a comma
- Items separated by `,`; spaces around items are trimmed
- **Item count MUST equal locator count** — use empty items (`,,`) to skip. With 12 locators, `"HQ0000020"` is invalid; write `"HQ0000020,,,,,,,,,,,"`
- Edit CSV files in **VS Code, not Excel** — Excel may save Thai in a non-UTF-8 encoding and turn values like `0812345678` or `11:00` into numbers/times
- Commas inside an item are not supported. If a button name contains a comma (e.g., `นวดหินร้อน ฿ 1,200`), write a unique part of the name: `นวดหินร้อน`. Playwright matches button names by substring; if the part matches several buttons, the test fails with a clear "multiple elements" error — make it longer.

### Workflow

1. Dev: codegen once → raw script
2. Dev: write `_flows/<feature>.ts` with markers
3. Dev: put locator lines in `_locators/<feature>.ts` → **Setup 3**
4. QA: write scenarios → **Setup 4** → `_scenarios/<feature>.csv`
5. **Setup 5** → 4 files generated
6. Run tests: `npx playwright test Test-Local/<Project>/<AccessFlow>/<Module>/<feature>`
7. Regenerate JSON cache: `analyze-project.bat`

## Section 8: 4-File Pattern (Reference)

The 4 files are generated by `scripts/setup-5.mjs`. **The script is the single source of truth for templates** — this section describes behavior only. Do not copy template code from this file.

| File | Generated from | Contents |
|---|---|---|
| `<feature>.types.ts` | — | `<Feature>TestCase { testCaseId, scenario, values: string[] }` |
| `<feature>.data.ts` | `_scenarios/` | One object per CSV row; `values` is a literal string array with exactly N items (empty = `''`) |
| `<feature>.helper.ts` | template | `apply<Feature>Inputs(page, testData)` — validates `values.length === locators.length` (throws otherwise), skips `''`, dispatches each item (Section 9) |
| `<feature>.spec.ts` | `_flows/` | `enter<Feature>Page` = SETUP; test body = pre-DATA + `apply<Feature>Inputs` + post-DATA + `defaultVerify` |

### How the files connect

```
_flows/<feature>.ts      ──(generation)──►  spec.ts
_scenarios/<feature>.csv ──(generation)──►  data.ts
_locators/<feature>.ts   ──(runtime import)─►  helper.ts   (import '../_locators/<feature>')
```

### Script guarantees

- Flow steps copied character-for-character (no renaming, no added steps)
- UTF-8 output, no BOM
- Stops without writing anything if: source file missing, marker missing/duplicated, Thai text corrupted (`à¸…`, `�`, UTF-16, `` `n ``), locator has default parameter, CSV row has wrong item count, `|click` given to a parametric locator, text given to a non-fillable static locator, duplicate TC-ID, feature folder already exists
- Warns (does not stop) if `authType` is missing/invalid

### After generation

- Editing `defaultVerify` to add feature-specific checks is fine
- Do not hand-edit flow steps in spec.ts — fix `_flows/` instead (delete the feature folder and rerun Setup 5, or edit both consistently)

## Section 9: Value + Locator Vocabulary

### Dispatch matrix

| CSV item | Locator shape | Action |
|---|---|---|
| `''` (empty) | any | Skip |
| `|click` | static | `locator.click()` |
| `|click` | parametric | **Error** — give a button name instead |
| text | parametric | `locatorFn(page, text).click()` — click element named `text` |
| text | static → element is a text field (`input` text/email/date/…, `textarea`, `contenteditable`, role textbox) | `.fill(text)` |
| text | static → native `<select>` | `.selectOption({ label: text })` |
| text | static → dropdown (role `combobox`, `aria-haspopup="listbox"`, button with `aria-expanded`, or a div/span opener such as `.ng-input` / placeholder text) | `selectOption(page, locator, text)` — open it, then click `option` named `text` |
| text | static → checkbox / radio / button / file input | **Error** — use `\|click`, or add an action via Setup 6 |
| `|<other>` | any | **Error** — Unknown action (add via Setup 6) |

Shape is detected at runtime by `locatorFn.length` (2 = parametric, 1 = static). For static locators the helper inspects the **element on the page** (`fieldKind()`), not the locator text, so `getByRole('textbox')`, `getByPlaceholder`, `getByLabel`, `#id` all work for text fields, and `combobox`, `.ng-input`, placeholder text all work for dropdowns.

**Dropdowns in `_flows`:** Setup 5 replaces a recorded "opener click + option click" pair (`getByRole('option', { name })` or `getByLabel('X').getByText('X')`) with `selectOption(page, <opener>, '<option>')`, and drops position-only clicks right before the opener (`locator('div'|'span').nth/first`, `.ng-input`, `combobox`) as repeated attempts to open the same dropdown. Each change is reported. Setup 5 also warns about position-only locators (`locator('div').nth(3)`, generated ids) in `_flows` and `_locators`.

### Supported actions

| Action | Implementation |
|---|---|
| `|click` | `target.click()` (static locators only) |

Not yet supported (add via Setup 6 when needed): `|check`, `|toggle`.

### Examples

| CSV Value (5 locators) | Result |
|---|---|
| `"นวดไทย,วันพฤหัสบดีที่ 1 ตุลาคม,11:00,test,0812345678"` | click 3 buttons by name, fill 2 textboxes |
| `"นวดไทย,วันพฤหัสบดีที่ 1 ตุลาคม,11:00,,"` | click 3 buttons, skip both textboxes |
| `"นวดไทย,วันพฤหัสบดีที่ 1 ตุลาคม,11:00"` | **Error** — 3 items, expected 5 |

| CSV Value (4 static locators: textbox, textbox, combobox, button) | Result |
|---|---|
| `"HQ0000020,,,"` | fill [0], skip rest |
| `"A,B,งานใหม่,|click"` | fill [0], fill [1], pick option [2], click [3] |
| `"click,,,"` | fill [0] with the text "click" (no `|` = text) |
